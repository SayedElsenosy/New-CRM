# مسار — إدارة توظيف الدليفري v1.3

واجهة عربية + بوت واتساب QR + Supabase + فهم ذكي محلي مجاني بدون Gemini أو OpenAI API. هذه الحزمة بديل نظيف لملفات النسخة السابقة، وليست ملفات تُخلط داخلها.

## ابدأ من هنا

للتشغيل المجاني على جهاز Windows افتح **docs/FREE_LOCAL_WINDOWS.md** وشغّل **START_FREE_WINDOWS.bat**. وللنشر السحابي افتح **docs/DEPLOY_AR.md**.

**Vercel وحده لا يستضيف جلسة Chromium/WhatsApp هذه كعملية دائمة.** التصميم المرفق: واجهة Vercel + خدمة Docker واحدة على Render بقرص دائم + قاعدة Supabase. التشغيل اليومي والربط والفصل من اللوحة. خدمة Render ذات القرص الدائم تحتاج خطة مدفوعة؛ راجع السعر المعروض قبل تفعيلها.

## الموجود في النسخة

- تسجيل دخول موظفين موثّقين؛ خدمة البوت تتحقق من JWT وقائمة الموظفين قبل أي قراءة بيانات أو إظهار QR.
- ربط واتساب QR، حالة حقيقية، فصل وإلغاء جلسة، واستعادة اتصال بعد إعادة تشغيل الخدمة.
- أسئلة قابلة للإضافة والتعديل والترتيب والتعطيل، مع نوع الإجابة ومفتاح حفظها وكونها مطلوبة/اختيارية.
- حفظ الإجابة مع نص السؤال ونوعه وتاريخها داخل ملف المتقدم، وعرض المحادثة والمرفقات.
- المناطق مصدر اختيار منطقة العمل ومصدر الرد على استفساراتها؛ لا توجد أرقام مرتبات مُختلقة في الكود.
- فهم ذكي محلي للردود المصرية غير المباشرة بدون API Key أو تكلفة لكل رسالة، ثم تحقق برمجي من الإجابة. لو الرد غامض يطلب البوت توضيحاً.
- الحالات التلقائية: جديد / لم يكمل البيانات / أرسل البيانات بالكامل. الحضور وبدء العمل بتأكيد الموظف، مع التاريخ وسجل إجراء.
- بحث وتصفيات وصفحات للمتقدمين، تقارير شاملة الفترة، وتجميع مناطق ومراحل وأيام، وتصدير CSV عربي يفتح في Excel.
- إرسال رد يدوي مع إيقاف البوت لهذا المتقدم، وإعادة تشغيله من ملفه.
- استيراد متكرر آمن للسجلات الأساسية القديمة من نفس قاعدة البيانات عبر الإعدادات؛ لا يحذف الجداول القديمة.
- طابور رسائل محفوظ بقاعدة البيانات؛ تحديث الإجابات وإنشاء الرد والإقرار بالرسالة عملية SQL واحدة. عند انقطاع الخدمة خلال الإرسال تظهر حالة «غير مؤكد» للمراجعة قبل إعادة الإرسال.

## قواعد مهمة في التشغيل

- حساب واتساب واحد وخدمة بوت واحدة (instance=1). لا تشغل البوت القديم بالتزامن مع الجديد.
- لا يُعرض `@lid` كرقم هاتف. يتم الاستعلام عن PN من واتساب؛ إذا تعذّر يظهر «الرقم غير متاح». الرقم لا يمكن اختراعه من LID. عند كشفه تُدمج هوية LID مع ملف الرقم إن كان موجوداً.
- «مكتمل» يعني وجود إجابات لكل الأسئلة المطلوبة المفعلة؛ لا يعني صحة المستندات أو قبول التعيين. إجابة «لا» محفوظة كما هي ولا تتحول إلى رفض أو قبول آلي.
- الأسئلة تتغير للخطوات القادمة. إضافة سؤال مطلوب قد تجعل ملفات كانت مكتملة تظهر كغير مكتملة. الحضور والعمل المثبتان لا يتغيران تلقائياً.
- المستندات المخزنة تُفتح بروابط خاصة مؤقتة. أنواع المرفقات: JPG / PNG / WebP / PDF حتى 10 MB. الصوت والفيديو والملصقات لا تُحلّل؛ تظهر مطالبة بمدخل مدعوم عند سؤال المستند.
- البوت لا يفهم الصور كهوية موثّقة ولا يستنتج الحضور من كلام المتقدم. تفسير الردود المطلوبة لمسار التوظيف يتم محلياً داخل الخدمة ولا تُرسل الرسائل لخدمة AI خارجية.
- المحادثات الجديدة تُحفظ من وقت تشغيل الخدمة. استيراد سجل النسخة القديمة يتم من الجداول؛ لا تسحب الحزمة كل سجل واتساب من الهاتف.
- استيراد النسخة القديمة يحفظ المحادثات ويعرضها، لكنه لا يستنتج إجابات منظمة أو ينقل ملفات Storage القديمة تلقائياً. تبقى البيانات الأصلية كما هي. راجع أنواع الأسئلة بعد الاستيراد.
- الملفات السرية والجلسات وnode_modules ونسخ Meta API القديمة غير موجودة في الحزمة. احتفظ بالنسخة الأصلية كنسخة احتياطية.

## خريطة الملفات

|---|---|
| admin-dashboard/src | الواجهة العربية وصفحات المتقدمين والأسئلة والمناطق وواتساب والتقارير |

| docs/DEPLOY_AR.md | دليل النشر والتشغيل من المتصفح |
| docs/TESTING.md | ما اختُبر وما يحتاج اختباراً فعلياً بعد الربط |
| vercel.json / render.yaml / Dockerfile | إعداد نشر الواجهة وخدمة البوت |
| .github/workflows/check.yml | بناء واختبار تلقائي عند الرفع إلى GitHub |

## للمطور فقط

Node.js 22+. من الجذر: `npm ci` ثم `npm test` و`npm run build`. للتطوير `npm run dev` ولخدمة البوت `npm start` بعد ضبط متغيرات البيئة. Docker يتضمن Chromium؛ في التطوير المحلي يحتاج whatsapp-web.js متصفح Puppeteer. هذه الأوامر ليست مطلوبة على جهاز صاحب المشروع عند اتباع دليل النشر.
