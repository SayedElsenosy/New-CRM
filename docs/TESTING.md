# التحقق من نسخة v1.3

## اختبارات منفذة محلياً

- اختبارات Node لمنطق المحادثة: حفظ الإجابات، العمر بالأرقام العربية، النفي، الأسئلة المطلوبة والاختيارية، استفسارات المناطق بدون التقدم الخاطئ، رفض منطقة متوقفة/مختلقة، وفشل Gemini بأمان.
- حماية عدم اعتبار LID رقم هاتف، وتحويل PN الذي يرجعه واتساب إلى رقم دولي.
- صلاحيات API: غياب الجلسة، جلسة غير صحيحة، مستخدم غير موظف، وOrigin غير مسموح؛ لا تسمح بتشغيل QR/الربط.
- دورة اتصال باستخدام عميل واتساب محاكى: الربط مرة واحدة، حالة الاتصال ورقم الحساب، وتنفيذ logout/destroy عند الفصل.
- تشغيل SQL على PostgreSQL محلي مؤقت عبر PGlite، مع محاكاة schemas الخاصة بـSupabase؛ فحص قابلية إعادة الترحيل، حفظ الإجابة والرد معاً، عدم تكرار الرد لنفس الرسالة، حماية حالات الحضور، ترتيب الأسئلة، ومنع anon من قراءة المتقدمين. خدمة Supabase الحقيقية وStorage ليستا محل اختبار مباشر هنا.
- `npm run build`: بناء إنتاجي ناجح للواجهة.
- فحص متصفح ببيانات وهمية: نظرة عامة، حفظ سؤال، حفظ منطقة، طلب الربط والفصل، ملف متقدم، إرسال رد يدوي إلى API المحاكى، التقارير، وتخطيط الموبايل بدون تجاوز عرض الشاشة. تمت معاينة صور الكمبيوتر والموبايل.

## ما لم يُختبر على حسابات فعلية

- مسح QR بحساب صاحب المشروع وإرسال/استقبال رسائل WhatsApp حقيقية.
- اتصال Supabase الخاص بالمستخدم أو استيراد بياناته الفعلية أو رفع مرفقات إليه.
- ردود Gemini الحقيقية على مفتاح المستخدم وحصة استخدامه.
- بناء Docker على Render أو نشر Vercel/GitHub؛ تم تجهيز الملفات ولم يتم إنشاء أو نشر خدمات خارجية.

## تشغيل الفحص تلقائياً

عند رفع `.github/workflows/check.yml` مع المشروع، ينفّذ GitHub Actions تثبيت المكتبات والاختبارات وبناء الواجهة. الفحص لا يرسل رسائل ولا يحتاج مفاتيح حسابات فعلية.

بعد النشر اتبع سيناريو الفحص الحقيقي في `DEPLOY_AR.md` قبل الاعتماد عليه مع المتقدمين.
