# المرحلة الثالثة — AI Quality Center

## مكانها في لوحة التحكم
افتح **AI Agent → مركز الجودة** (صفحة للـ Admin فقط). هتلاقي فترة قياس 24 ساعة / 7 أيام / 30 يوم، ولوحة أدوات، ومجموعة اختبارات آمنة قابلة للتشغيل، وحالات تقييم مخصصة للـ Planner.

## المقاييس الحقيقية
تُحسب في `GET /api/agent/quality/metrics?days=7` من آخر سجلات `masar_events` و`masar_agent_decisions` و`masar_agent_eval_runs`، وتُعرض **كمجاميع فقط**. لا ترجع الرسالة الأصلية أو اسم/رقم المرشح أو applicant_id.

| مؤشر | يعني إيه؟ | لا يعني إيه؟ |
| --- | --- | --- |
| أدوار Agent | عدد `agent_turn` في الفترة | مش عدد المتقدمين الفريدين |
| نجاح أدوات CRM | `crm_tools.ok / crm_tools.total` | مش دقة كل إجابات البوت |
| Handoff rate | الأدوار اللي تحولت لمسؤول / إجمالي الأدوار | مش دليل وحده إن الأداء وحش |
| Fallback rate | سجل Decision فيه `fallback_used=true` / القرارات | مش كل فشل في الخدمة الخارجية |
| اختبار Planner Pass rate | الحالات `passed=true` من الحالات اللي لها حكم | مش مقياس جودة عام من المحادثات الحقيقية |
| Usage Tokens | القيم اللي مزود الـLLM رجعها للمحرك | مش تكلفة بالجنيه أو الدولار |

**التكلفة الفعلية غير متاحة** من السجلات الحالية لأن تسعير الموديلات/المزود غير معروف؛ لا نخترع قيمة. التوكنز تُعرض فقط لو المزود قدم `usage.prompt_tokens` و`usage.completion_tokens`. البيانات القديمة غالبًا ما فيهاش Usage. لو فيه أكثر من 5000 سجل Audit في نافذة التقرير، يظهر تحذير إن العرض **عينة جزئية**.

## الاختبارات المدمجة المجانية
زر «تشغيل الاختبارات» → `POST /api/agent/quality/suite/run` مشغل **داخل الخادم** على مكتب افتراضي ومتقدمين افتراضيين. يتضمن مجموعة Regression Tests باللهجة المصرية تشمل:
- تفاصيل الماركت والمطاعم حرفيًا، بدون تغيير الأرقام
- أسئلة في نفس الرسالة (قرب، مقارنة، حالة طلب)
- الطلبات الناقصة والتحويل البشري عند فقدان مستند
- تجربة معاينة منطقة ثم تأكيدها، ورفض التأكيد المزوّر
- منع اعتماد مكان السكن كمنطقة العمل
- العزل بين مكاتب مختلفة، وعدم إفشاء بيانات مكتب آخر
- تصحيح تفضيل الشيفت في الذاكرة

المجموعة الحالية: **21 سيناريو مستقلاً**، وتُنفّذ أيضًا في `npm test`. **لا تتصل بواتساب، ولا تغير Applicant حقيقي، ولا تستدعي LLM خارجي**. يظهر نجاح/فشل كل حالة وسبب الفشل، ويتم حفظ **المجموع فقط** في حدث `agent_quality_suite` لتتبع التحسن. الاختبارات توضح وجود أخطاء Regression، لكنها لا تثبت أن كل الردود خالية من الهلوسة.

## اختبارات مخصصة
من نفس الشاشة أدخل *رسالة مصرية افتراضية* وقرار Planner متوقع. تنحفظ في جداول تقييم الـAgent الحالية، وتشغيلها يعتمد على اتصال LLM فعلي (ويستهلك رصيد المزود). يمنع الخادم إضافة أرقام هاتف/بطاقات وبريد إلكتروني مباشر في حالات الاختبار الجديدة. لا تستخدم رسائل عملاء حقيقيين ولا أسرارًا.

## التحكم والصلاحيات
- بيانات الجودة في API محمية بـ `adminRoute`، ومقيدة بعدد أيام 1 إلى 30.
- لا تحتاج لعمل migration جديدة إذا كانت جداول Phase Agent Control Plane (`supabase/023_ai_agent_control_plane.sql`) مفعلة بالفعل.
- إذا الجداول غير موجودة، بعض أرقام التقييم لا تظهر (—) بدل الإدعاء بوجود بيانات.
- تشغيل الاختبار المدمج من الواجهة آمن ومحدود ولا يرسل أي رسائل خارجية.
- لا تُستخدم النتائج لتغيير Qualification أو إرسال رسائل للمرشحين أو إيقاف Agent تلقائيًا.

## اختبار الإصدار
```bash
npm test
npm run build
```

وبعد اكتمال نشر Railway افتح AI Agent → مركز الجودة، اختر أسبوع، شغل المجموعة؛ راجع معدل الاجتياز وخط الأخطاء ونجاح الأدوات، ثم اعمل مراجعة بشرية لعينة محادثات حقيقية في ملفات المتقدمين المصرح لها.

التحسينات التالية الممكنة: تحليلات حسب المكتب/نموذج LLM، معايير معيارية بشرية، اختبارات A/B، ورصد الانحراف عبر الزمن، والتنبيه عند ارتفاع حالات الفشل.
