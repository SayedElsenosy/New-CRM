# تشغيل الـAgent الجديد على الإنتاج

هذا الملف هو قائمة التنفيذ بعد دمج طبقات الـAgent المستقل لكل مكتب والتعلم المستمر.

## 1) قاعدة البيانات

من Supabase SQL Editor شغّل بالترتيب:

1. `supabase/017_autonomous_office_agent.sql`
2. `supabase/018_agent_memory_reliability.sql`

الملفان آمنان لإعادة التشغيل، لكن يفضّل أخذ Backup قبل أي migration على الإنتاج.

### تحقق سريع بعد 017

- `masar_office_settings.agent_enabled` موجود وقيمته الافتراضية `true`.
- `masar_questions` يحتوي:
  - `agent_instruction`
  - `priority`
  - `allow_inference`
  - `confirmation_required`
- `masar_knowledge.office_id` موجود.
- التعلم العام أصبح `live` ومستمر، ولا يوجد اعتماد تشغيلي على نافذة 3 أيام.

### تحقق سريع بعد 018

- `masar_knowledge` يحتوي:
  - `memory_status`
  - `evidence_count`
  - `conflict_count`
  - `confidence`
  - `last_verified_at`
  - `valid_from`
  - `valid_until`
  - `version`
- الجداول:
  - `masar_knowledge_evidence`
  - `masar_knowledge_versions`

## 2) نشر الكود

آخر فرع مطلوب: `main`.

الخدمة الخلفية تستخدم Docker وHealth Check:
- المسار: `/health`
- يجب أن يرجع `{"ok":true}`.

لو الاستضافة مرتبطة بـGitHub Auto Deploy، تأكد أن آخر deploy مبني من آخر commit على `main`.

الواجهة تحتاج إعادة Build/Deploy لأن تغييرات صفحة ذكاء الـAgent وإعدادات المكتب Frontend changes.

## 3) صلاحيات الواجهة

### Admin النظام

يجب أن يرى:
- صفحة ذكاء الـAgent.
- إعدادات الثقة والذاكرة.
- Autonomy Rate.
- Failure Clusters.
- تعارضات الذاكرة.
- History / Rollback.

### مدير المكتب `office_admin`

يجب أن يرى داخل إعدادات مكتبه فقط:
- زر تشغيل/إيقاف Agent المكتب.

ولا يجب أن يرى:
- إعدادات الثقة العامة.
- تغيير سياسة الذكاء المركزية.
- إدارة ذاكرة المكاتب الأخرى.

### Recruiter

لا يجب أن يرى زر تشغيل/إيقاف Agent المكتب.

## 4) اختبار عزل المكاتب

استخدم مكتبين A وB.

1. أوقف Agent في مكتب A.
2. اترك Agent مكتب B شغال.
3. ابعت رسالة لمتقدم في A: لا يجب أن يرد Agent.
4. ابعت رسالة لمتقدم في B: يجب أن يعمل طبيعيًا.
5. خلي موظف مكتب A يرد يدويًا بمعلومة تشغيلية.
6. التعلم يجب أن يستمر في A رغم توقف الردود.
7. المعلومة التي تعلمها A لا يجب أن تظهر في رد B.

## 5) اختبار Dynamic Interview

جرّب:

- `اه معايا موتوسيكل واسمي محمد احمد وعايز أكتوبر`
  - يحفظ الموتوسيكل + الاسم + منطقة العمل.
  - لا يعيد الأسئلة الثلاثة.
  - يسأل عن أهم معلومة ناقصة.

- `اه معايا مكنة وعايز أكتوبر بس المرتب كام؟`
  - يحفظ الحقائق.
  - يرد على المرتب من الذاكرة.
  - يكمل بالمعلومة الناقصة.

- `aywa m3aya moto w 3ayz october`
  - يفهم Franco الشائع.
  - يحفظ الموتوسيكل والمنطقة.

- `لا لا قصدي معايا مكنة`
  - يعاملها كتعديل/تصحيح حسب سياق المحادثة، وليس رفضًا جديدًا.

## 6) اختبار المناطق

- زر منطقة مفعلة يجب أن يحفظ المنطقة فورًا.
- يظهر تفاصيل المنطقة أولًا.
- السؤال التالي يرسل في رسالة منفصلة.
- أي منطقة مفعلة في قسم المناطق تعتبر متاحة للـGeo Qualification.
- `residence_area` لا يدخل في Qualification.

## 7) اختبار الذاكرة

1. اسأل عن معلومة موجودة: Agent يرد بها.
2. موظف يضيف قاعدة تشغيلية جديدة أثناء محادثة: يجب أن تتعلم تلقائيًا.
3. رد شخصي مثل `ميعادك بكرة الساعة 3`: لا يتحول لقاعدة عامة.
4. موظفان يقولان رقمين متعارضين لنفس المعلومة:
   - تتحول الذاكرة إلى `conflict`.
   - Agent لا يستخدمها في الرد.
5. من صفحة ذكاء الـAgent:
   - صحح المعلومة.
   - افتح History.
   - جرّب Rollback لنسخة سابقة.

## 8) اختبار Handoff

- سؤال غير معروف: Agent يحاول clarification قبل التحويل.
- بعد تكرار عدم الفهم: Handoff.
- `عايز أكلم موظف`: Handoff فوري.
- التنبيه البشري يجب أن يحتوي سبب التحويل.

## 9) مؤشرات الاعتماد

بعد تشغيل Live راقب من صفحة ذكاء الـAgent:
- Autonomy Rate آخر 30 يوم.
- Handoff Rate.
- أسباب Handoff.
- Knowledge usage.
- عدد المحادثات التي استخرج منها Facts.

أي سبب Handoff متكرر يعتبر Failure Cluster ونستخدمه كأولوية التطوير التالية.

## 10) قرار Go Live

لا نعتبر النسخة جاهزة للاعتماد الكامل إلا بعد نجاح:
- migrations 017 و018.
- backend health.
- frontend deploy.
- عزل مكتبين.
- زر مدير المكتب.
- Dynamic Interview.
- Franco.
- Knowledge conflict.
- Handoff.
- WhatsApp live message round-trip.
